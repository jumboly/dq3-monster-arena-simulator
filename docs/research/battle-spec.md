本書は公開解析資料だけを根拠に、SFC 版ドラゴンクエストIII の格闘場戦闘を実装するための仕様をまとめたもの。
コードは書かない（擬似コードのみ）。FC / GBC / スマホ版の情報は一切混ぜない。

### 0.3 アドレス表記と資料間の差異（重要）

- RGH は `$02xxxx`、dqbook は `$C2xxxx` と書くが同一領域（HiROM の別名）。本書は RGH 側の `$02xxxx` 表記に揃える。
- RGH の解説は **DQ3 Extended 1.43 パッチ適用 ROM** をベースにしている（RGH-005 冒頭）。コードのアドレスはオリジナルと同じだが、**戦闘行動構造体の位置だけが違う**（RGH は `$020060`、オリジナルは `$C21860`）。
  - RGH の `SR:$02CC25 引数1:#$00xx` のオフセットは **「dqbook のオフセット + #$60」** に対応する。例: RGH `#$007C mask #$0002` ＝ dqbook `#$1C bit #$02`（格闘場使用許可）。本書では両方を併記する。
- `$7E2030` 戦闘員構造体のオフセットは、RGH が「`$2020 + オフセット`」（例: 素早さ `$2043`）で書き、dqbook は構造体先頭 `#$00` 基準（例: すばやさ `#$13`）で書く。`$2020 + x` ＝ dqbook `#$(x-#$10)`。

### 0.4 型契約との対応

用語は `src/core/battle/types.ts` / `src/core/data/types.ts` に合わせる（`CombatantState.groupId`, `MonsterDef.strategy` など）。契約に足りないものは §11 に提案として列挙する。

## 1. 戦闘メインループ（`$0259F5`）

### 1.1 流れ 【Confirmed】 出典: RGH-002 `$0259F5`

通常戦・イベント戦・格闘場のすべてが同じループを通る。

```
battleMain():                                 // $0259F5
  initBattleRam()                             // $025A56  $7E2030-$7E27FF を 0 クリア、$2462-$2466 を $FF
  setupPartyCombatants()                      // $025A78  格闘場なら何もしない（§1.2 #1）
  setupMonsterCombatants()                    // $025AC7  あやしいかげ実体決定を含む（§2）
  monsterBattleStart()                        // $025B8B  Group 4 移動など（§2.3）
  if checkBattleEnd() goto END                // $02B32F（§8.1）
  loop:
    turnStart()                               // $025CC0（§3.1）
    partyCommandInput()                       // $025DEE  格闘場では PC が居ないので実質何もしない（Likely）
    if checkBattleEnd() goto END              // $02B32F
    decideTurnAgility()                       // $025D56（§3.2）
    decideMonsterActions()                    // $026464（§4）
    fixActionOrder()                          // $0263A2（§3.3）
    if executeOneTurn() goto END              // $027275（§6）  途中で決着したら c=on
    if checkTurnLimit() goto END              // $02A48C（§8.3） c=off なら loop へ
  END:
    if battleEndProcess() goto battleMain+init // $02A4E6  c=on なら $025A05 から戦闘をやり直す
    $2012++                                   // 累積戦闘回数
```

### 1.2 格闘場モード（`$7E2011` bit6 = `#$40`）で分岐する箇所の全列挙

`$7E2011` の bit 構成（RGH-003）: bit0-1 先制/強襲, **bit2-3 賭けたモンスターの添字 0..3**, bit4 逃走不可, bit5 イベント戦, **bit6 格闘場**。

| # | アドレス | 内容 | ラベル | 出典 |
|---|---|---|---|---|
| 1 | `$025A8A`-`$025A8E` | 格闘場なら PC 側戦闘員の登録を丸ごとスキップ（Group 5 が存在しない） | Confirmed | RGH-005 `$025A78` |
| 2 | `$025C6A`-`$025C6E` | 格闘場なら賭けた選手を Group 4 へ移す（§2.3） | Confirmed | RGH-006 `$025C61` |
| 3 | `$02B36B`-`$02B371` | 終了タイプ表の添字を +1（勝利→当たり、全滅→ハズレ） | Confirmed | RGH-006 `$02B32F` |
| 4 | `$02B38C`-`$02B3B2` | 格闘場なら生存者数を数え、0 体→引き分け(7)、1 体→終了、2 体以上→続行 | Confirmed | RGH-006 `$02B32F` |
| 5 | `$0268FB`-`$026909` | 格闘場ではコマンドの「格闘場使用許可」(dqbook `#$1C bit#$02` / RGH `#$007C mask#$0002`)が 0 のコマンドを選択不可にする | Confirmed | RGH-011, RGH-011-4 `$0268ED` |
| 6 | `$02A4A2`-`$02A4CC` | 格闘場ならターン上限 10（通常は 65535） | Confirmed | RGH-024 `$02A48C` |
| 7 | `$02729E` | `SR:$027329`「格闘場中断処理?」を各行動主体の手番ごとに呼ぶ（中身未公開） | Unknown | RGH-014 `$027275` |
| 8 | `$02A512` | 終了タイプ(5/6/7)ごとの戦後処理ジャンプ（配当処理を含むと思われるが中身未公開） | Unknown | RGH-024 `$02A4E6` |

補足:
- 格闘場判定そのものではないが、**グループ ID ≥ 4 / ≥ 5 による分岐**が格闘場の Group 4 に効く。§7.8 に全列挙する。
- 格闘場でイベント戦フラグ(bit5)が立つか、先制/強襲(bit0-1)が非 0 になるかは未公開。【Likely】どちらも 0（通常・非イベント）として扱う。影響先: 先制/強襲なら `$0264FA` の行動抑止、イベント戦ならパルプンテ・一撃必殺の制限（格闘場の出場モンスターは使わない）。

## 2. モンスター戦闘員の初期化

### 2.1 `$025AC7` モンスター戦闘中情報設定 【Confirmed】 出典: RGH-005

```
for slot in 0..3:                              // X = slot*2
  count = $2008[slot]  (出現数)
  id    = $2000[slot]  (モンスター ID)
  if count == 0 or id == 0: continue
  entityId = id
  if id == #$19 (あやしいかげ): entityId = decideShadowEntity()   // $025B46（§2.4）
  repeat count times:
    addCombatant(selfId=id, transformId=entityId, group=slot, isPartySide=0)   // $02AB00
    combatant.$203A = $2456; $2456 += 2       // 表示用の連番（dqbook は $203A を「敵アニメーション」と呼ぶ）
```

- `addCombatant` = `$02AB00`: 空きスロット検索(`$02AC31`) → 1 体分 0 クリア(`$02AD55`) → `$2050 bit#$02`(アクティブ)=1, `$203C`(グループ)=slot, `$2049`(自分自身)=id, `$204B`(変身相手)=entityId, `$2050 bit#$01`(自陣側フラグ)=0, `$2051 bit#$01`=0, 基礎ステータス設定(`$02ABA1`→`$02ABAE`), `$23FE[group]=id`, `$240E[group]++`。
- **格闘場の出場モンスターも通常戦と全く同じ経路で初期化される**（`$025AC7` に格闘場分岐はない）。【Confirmed】
- 格闘場で `$2000-$2008` がどう埋まるか（各選手が別グループ・出現数 1 か）は `$C3EC84` 側で未公開。【Likely】試合カードの k 番目の選手 → slot k、出現数 1。根拠: 賭け対象を「グループ番号 0..3」として `$7E2011 bit2-3` に保持し、`$025C61` がそのグループ全員を Group 4 に移している（1 グループ = 1 選手でないと賭けの単位が成立しない）。
- 戦闘員インデックス（0..23）の割当順は `$02AC31` 未公開。【Unknown】暫定: slot 順に 0,1,2,3。※行動順のタイブレーク（§3.3）に効く（U-22）。

### 2.3 `$025B8B` → `$025C61` 賭けた選手を Group 4 へ移す 【Confirmed】 出典: RGH-006

```
if not arena: return
g = ($7E2011 & #$0C) (bit2-3 を取り出した 0..3)       // $09029E 経由。右詰めされるのは Likely
$23FE[4] = $23FE[g]; $23FE[g] = 0                   // グループ別モンスター ID
$240E[4] = $240E[g]; $240E[g] = 0                   // グループ別出現数

  if active(x) and group(x) == g: group(x) = 4
```

- 以後、賭けた選手は `groupId = 4`、元のグループ g は空になる。`originalGroupId` は契約上保持してよいが、ROM 上は上書きされて失われる。
- `$025B8B` のその他（出現メッセージ、先制/強襲情報コピー `$025C02`、デバッグ窓）は戦闘結果に影響しない。

### 2.4 あやしいかげ（ID `#$19`）の実体決定 `$025B46` 【Confirmed】 出典: RGH-005

```
decideShadowEntity():
  L = level(partyMember[0]) + 1            // $042FEB 引数(A=0) = 先頭キャラクターのレベル
  buf = []
  for id in #$83 down to #$01:             // キングヒドラ → スライム
    if monsterLevel(id) < L: buf.push(id)  // monsterLevel ≤ 先頭レベル
  return buf[ rand0toA(len(buf) - 1) ]     // $00133E（0..A 閉区間）→ 一様選択
```

- 候補には ID `#$19`（あやしいかげ自身）やボス（やまたのおろち等）も含まれる（RGH-TRIVIA「レベル63以上でやまたのおろち(1,2共に)」）。【Confirmed】
- 「先頭 PC」は主人公固定ではなく並び順の先頭。【Confirmed】（`$042FEB` 引数 A=0）。格闘場では入場時の隊列先頭。
- 決定した実体 ID は `$204B`（変身相手）に入り、戦闘員のステータスは実体側から取ると思われる。【Likely】（dqbook-combatants「変身相手」: 見かけ上あやしいかげなら正体のモンスター ID）。どのフィールド（HP・コマンド・耐性・行動パターン）を実体から取るかの厳密な確認は未了。【Unknown】→ U-10
- 撃破時 `$02BAE8` で名前等を正体に差し替える（表示用）。

### 2.5 同一モンスター識別子

- dqbook `#$0B`（`$203B`）。敵陣で同じ ID が複数いるときの A/B/C 表記用の 0 からの連番。【Likely】（dqbook-combatants）

### 3.2 `$025D56` ターン中の素早さ 【Confirmed】 出典: RGH-009

```
for x in 23..0:
  if not active(x) or dead(x): turnAgi[x] = 0
  else:
    r = rand00FF_b()                                  // $001457（$00-FF）
    turnAgi[x] = floor(((agility(x) + 20) * r) / 256) + 1
  $2045(x) = turnAgi[x]                               // dqbook「コマンド実行優位」(#$15)
orderBy($2484)                                        // $025DAC（§3.3 と同じソート）
```

- `agility(x)` は戦闘中の現在値 `$2043`（ボミオス等で変化した値）。【Confirmed】
- 乗算 `$0010D6` は 16bit×8bit→24bit、上位 2 バイト（`$01-$02`）を採用 = 256 で割って切り捨て。【Confirmed】
- ここで一度並べた順番（`$23B8[]`）が、**モンスター行動決定（§4）を呼ぶ順番**になる。【Confirmed】（`$026464` は `$23B8[0..23]` を順に走査）

### 3.3 `$0263A2` 行動順序補正 → `$025DAC` 行動順決定 【Confirmed】 出典: RGH-013

```
for x in 0..23:
  key[x] = 0
  if not active(x) or dead(x): continue
  cmd0 = action[x][0]
  bonus = astronPriority(cmd0)        // $026436「アストロン詠唱ならターンの最初にする」→ $00
  key[x] = $2045(x) + bonus + 1
  for k in 0..2: if action[x][k] is 防御系 and 般若の面非装備: $2050.bit7(防御状態) = 1   // $026446

```

`$025DAC`（Confirmed）:
```
order = []
repeat:
  best = none; bestVal = 0
  for x in 0..23:                     // インデックス昇順
    if key[x] > bestVal: best = x; bestVal = key[x]    // 厳密に大きいときだけ更新

```
- **同値はインデックスの小さい戦闘員が先**。key=0（非アクティブ・死亡）は並ばない。【Confirmed】
- `bonus` は通常 0 と思われる（格闘場の出場モンスターはアストロンを持たない）。【Likely】
- 防御（モンスター用コマンド `#$68`「みをまもっている」）の防御状態は、実行前のこの段階で立つ。【Likely】（`$026446` の名前のみ公開）。※§4.1 の「神」が行動直前に防御を選んだ場合はここを通らない点に注意（U-05）。

## 4. モンスター行動決定（`$026464`〜）

### 4.1 `$026464` / `$02648B` 枠組み 【Confirmed】 出典: RGH-010

```

  x = order[y]; if x >= 24: continue
  if not active(x): continue
  if isPartySide(x) and not dragoramed(x): continue      // $02B416
  if suppressedByAmbushOrFailedEscape(x): continue       // $0264FA（格闘場では通常 0 なので素通り: Likely）
  if dead(x): continue

      resetAction(x); continue                           // $02B4F1 → 行動なし
```

## 7. ダメージ計算

### 7.1 通常攻撃の基本ダメージ `$028DB0` → `$028E0E`（モンスター側） 【Confirmed】 出典: RGH-020

**行動主体のグループが 5 未満（Group 4 を含む全モンスター）はこの式。**

```
A = attack(actor)            // $203F（現在値）
D = defense(target)          // $2041（現在値。ルカナン・スクルト反映後）
d  = A - floor(D/2)          // 16bit 符号付き（負なら bit15）
a8 = floor(A/8)
if d < 0 or a8 >= d:
    if A >= 16: dmg = rand0toA(a8 - 1)          // 0 .. a8-1
    else:       dmg = rand00FF() & 1             // 0 or 1
else:
    if A < 8:   dmg = rand00FF() & 1
    else:       dmg = floor(d * rand63to99() / 256)   // $001472: $63-$99 = 99..153
```
- `rand0toA` の引数は 1 バイト（A ≤ 255）。格闘場の攻撃力（最大 200）では問題なし。

## 8. 戦闘終了判定

### 8.1 `$02B32F` 戦闘終了時フラグセット 【Confirmed（コード）/ Likely（サブルーチンの意味）】 出典: RGH-006

```
checkBattleEnd():                  // c=on で終了
  t = $23AB & #$0F                 // 戦闘終了タイプ
  if t != 0 and t != 6: return END // 既に確定している（6 = ハズレ は「暫定」扱いで再評価される）
  if sideA_alive() == 0 ($02B3C5): x = 0
  else if sideB_alive() == 0 ($02B3E8): x = 2
  else: return CONTINUE
  if arena: x += 1
  $23AB.low = table_$02B3C1[x]     // Likely: [1 勝利, 5 格闘場当たり, 2 全滅, 6 格闘場ハズレ]
  if not arena: return END
  cand = aliveAll()                // $02C739(引数0)「生存者ビットを残す」
  n = count(cand)                  // $0270E1
  if n == 0: $23AB.low = 7 (引き分け); return END
  if n >= 2: return CONTINUE       // ★ タイプ 6 は書いたまま続行
  return END                       // n == 1
```

終了タイプ（`$7E23AB` bit0-3, RGH-003）: 1 勝利 / 2 全滅 / 3 逃走 / 4 65535 ターン / **5 格闘場当たり / 6 格闘場ハズレ / 7 格闘場引き分け**。【Confirmed】

### 8.2 格闘場の勝者判定（まとめ）

`$02B3C5` = Group 0-3 の生存判定、`$02B3E8` = Group ≥ 4（格闘場では賭けた選手）の生存判定、と読むと全分岐が終了タイプの意味と整合する。【Likely】

| 状況（1 行動の直後に判定） | 終了タイプ | 戦闘 |
|---|---|---|
| Group 0-3 が全滅、賭けた選手が生存（n=1） | 5 当たり | 終了 |
| Group 0-3 が全滅、賭けた選手も死亡（n=0） | 7 引き分け | 終了 |
| 賭けた選手が死亡、他が 2 体以上生存 | 6（暫定） | **続行**（残りが戦い続ける） |
| 賭けた選手が死亡、他が 1 体だけ生存 | 6 ハズレ | 終了 |
| 賭けた選手が死亡後、残りが相打ち等で 0 体 | **7 引き分け**（賭けた選手が先に死んでいても引き分けになる） | 終了 |

- **「生存 1 体で決着、0 体で引き分け」の根拠**は `$02B392`-`$02B3B2`（n==0 → 7、n≥2 → 続行、それ以外 → 終了）。【Confirmed】
- 「生存」の定義（死亡・マヒ・非アクティブ(バシルーラ) をどう数えるか）は `$02B3C5`/`$02B3E8`/`$02C739`/`$02C766` の中身が未公開。【Unknown】→ U-15
  - 暫定: 「アクティブ かつ 死亡でない」を生存とする（マヒ・眠り・混乱は生存に数える）。根拠: `$02661F` で「生存者だけ残す」`$02C766` が対象選択（マヒ者も対象になりうる）に使われている、dqbook「アクティブフラグ」の定義。通常戦の「全員マヒで全滅」が格闘場の決着にも効くかが最重要の確認点。
- 決着は 1 行動ごとに判定されるので、全体攻撃で同時に複数が倒れた場合は「その行動の後」の状態で判定する（複数対象の処理順は戦闘員インデックス昇順、§6.3）。【Confirmed】

### 8.3 ターン数オーバー `$02A48C` 【Confirmed】 出典: RGH-024

```
checkTurnLimit():                // c=on で終了
  $23D0++                        // 経過ターン数
  if not arena: 65535 以上で終了タイプ 4
  else if $23D0 >= 10:
     if ($23AB & #$0F) == 0: $23AB.low = 7 (引き分け)
     return END                  // 0 でなければ（= 6 ハズレ暫定）そのまま 6 で終了

```
- **10 ターン目の全行動とターン終了処理を実行した後に判定**する（`$027275` が c=off で戻った後にだけ呼ばれる）。つまり最大 10 ターン。【Confirmed】
- 10 ターン終了時点で賭けた選手が生存 → 引き分け(7)。**賭けた選手が既に死んでいて他が 2 体以上残っている → ハズレ(6)**（引き分けではない）。【Confirmed】
- 10 ターン目の途中で決着した場合は `$027275` が c=on で抜け、`$02A48C` は呼ばれない。【Confirmed】

### 8.4 `$02A4E6` 戦闘終了判定+終了処理

## 9. 乱数（RNG）

乱数生成器の**アルゴリズム（状態・更新式・シード）はどの公開資料にも載っていない**。【Unknown】→ U-16。
以下は「呼び出し口と値域」だけ。実装では、将来 `SfcDq3Rng` に差し替えられるよう、Battle Core は下の名前付きプリミティブ経由で乱数を引くこと（§11 提案 P-06）。

  4. `$02A41F`: 自動回復（格闘場では 0 なので消費しないと思われる: Likely）。
